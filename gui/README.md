# Herbarium GUI

This folder contains two user interfaces for demoing and running inference with the project approaches:

- `tk_app.py` — A lightweight desktop GUI built with Tkinter. Good for quick local demos and browsing example images. Use when you want a simple desktop window.
- `streamlit_app.py` — A web UI implemented with Streamlit. Mimics a HuggingFace-like demo (large upload area, submit button, sample images and prediction panel). Use when you want a polished browser-based demo.

## Running

Activate your virtual environment and run the desired app.

Tkinter (desktop):
```powershell
& "./.venv/Scripts/Activate.ps1"
& "./.venv/Scripts/python.exe" "./gui/tk_app.py"
```

Streamlit (web):
```powershell
& "./.venv/Scripts/Activate.ps1"
& "./.venv/Scripts/python.exe" -m streamlit run "./gui/streamlit_app.py"
```

Notes:
- Run the Streamlit server with `streamlit run` — importing the module directly will produce Streamlit warnings (that's expected).
- Make sure required Python packages in `requirements.txt` are installed into your venv (torch, timm, torchvision, pillow, joblib, streamlit, scikit-learn, numpy).

## Expected files / formats

- Approach 3 checkpoint: a PyTorch `.pt` file containing keys: `proj_state`, `clf_state`, and `class_ids` (the training scripts in `Approach 3/` produce these).
- Approach 1 checkpoint: a PyTorch `.pt` containing `feature_extractor_state_dict` and `classifier_state_dict` as used in the `cdna_pipeline` code.
- Approach 2 classifier: a joblib `.pkl` or `.joblib` file containing either a sklearn classifier object, or a dict with `'model'` (the classifier) and optional `'classes'` list. Extractor weights are optional — if missing, the apps fall back to the Approach 3 DINOv2 extractor for demos.

## Tips

- If the GUI reports 'module import' errors for Approach 1/2, make sure the corresponding subfolders (`Approach 1/cdna_pipeline` and `Approach 2/Approach2_v1/src`) are present and contain the expected modules.
- For Approach 2, the classifier's `classes_` may use compact indices (0..K-1); the GUI attempts to remap indices using `Approach 2/Approach2_v1/features/train.npz` when available.
- Use the 'File → Run Batch' option in the Tkinter GUI to process multiple images and export a CSV of results.

## Quick workflow

1. Start the Streamlit demo.
2. Select the approach and provide the required checkpoint/classifier paths in the right-hand controls.
3. Upload an image on the left, press Submit.
4. View Top‑K predictions and example images for the top prediction.

# GUI: Herbarium Model Explorer (Streamlit)

This small Streamlit app lets you load a trained checkpoint from this repo, upload or pick an image, and view Top-K predictions and example images for the predicted class.

Files:
- `streamlit_app.py`: main app

Run (from project root, with venv activated):

```powershell
& .venv/Scripts/Activate.ps1
pip install -r requirements.txt
streamlit run gui/streamlit_app.py
```

Notes:
- The app uses `approach3.eval_core.load_model_for_eval(ckpt, data_root)` to load model and preprocessing; that function must be present and compatible.
- If your checkpoint path is relative, the working directory is the project root; use absolute paths if needed.
- The `data_root` should point to `AML_project_herbarium_dataset` (the folder that contains `train/`, `list/`, etc.).

Additional features:
- **GPU toggle**: The Streamlit app has a "Use GPU if available" checkbox. Enable it to run inference on CUDA when available.
- **Caching**: Approach 3 model loading and Approach 2 classifier/extractor loading are cached by Streamlit (`@st.cache_resource`) to speed repeated inferences.
- **Top‑K gallery**: After running inference, the app displays a horizontal gallery of example images for the Top‑K predicted classes (up to 6 thumbnails).

----------------
